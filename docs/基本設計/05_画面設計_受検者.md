### 1.3 セッション状態と画面の対応

サーバ（Server Component）がどの画面を返すかは、11-1 §2.1.2 の表が正です（1.x 版の本節の表を置き換えた）。判定は `lib/auth/respondent-page-guard.ts` の `guardRespondentPage`（§10.6）が行い、ブラウザ側の状態に依存しません。

- `/`・`/exam` は Cookie を見ずに R-01 を出します（URL に「amp;」があれば先にリダイレクト。11-1 §2.2.1）。
- `/exam/{sessionId}` は、未開始なら R-02、開始済みなら `/questions` へ、送信済みなら `/complete` へリダイレクトします。`/questions` は、未開始なら `/exam/{sessionId}` へ、送信済みなら `/complete` へリダイレクトし、開始済みなら R-03 を今のステップ（§6.2）で出します。`/complete` は、送信前なら `/exam/{sessionId}` へリダイレクトし、送信済みなら R-05 を出します。
- Cookie の検証は変わりません: Server Component は 04 §2.5.2 の `requireRespondentSessionFromCookies(sessionId)`（`next/headers` の `cookies()` から `tk_session` を読む）を呼び、トークンのハッシュの一致・期限・`deletedAt == null`・パスの `{sessionId}` の一致を確かめます。検証に失敗したとき（401 `RESPONDENT_TOKEN_INVALID`・`RESPONDENT_TOKEN_EXPIRED`、404 `NOT_FOUND`）と組織が論理削除されているときは、理由を区別せずに R-06（`session_unavailable`）を出します。
- トークンの検証は `status` に依存しません（送信後も R-05 を出すため。D05-15）。保存・送信の API が `submitted` を 409 で拒否する点（04）は変わりません。

### 8.1 コントラストの基準

| 対象 | 基準 |
|---|---|
| 文字 | 文字と地の組は 4.5:1 以上。文字の大きさで分けない（大きい文字の 3:1 の緩和を使わない）。ホバー・押下・フォーカスのとき・選んだとき・リンクを訪れたあとの組も同じに確かめる（K-48） |
| 意味を持つ部品 | 見分けられないと操作や状態が分からない部品（入力欄・プルダウンの枠、プルダウンの矢印、ラジオボタンの円、選んだ状態の印、選択肢カード（ラジオの選択肢を押せる範囲を枠で示す部品）、焦点の枠、アイコンだけのボタンなど）は、隣の色と 3:1 以上。マウスを載せたとき・押したとき・フォーカスのとき・選んだとき・不正のときの色も同じに確かめる（K-50） |
| 隣の色 | 枠は、接するすべての色（部品の外の地と、部品の中の地）と比べ、どちらとも基準以上にする。矢印・選んだ点など部品の中の印は、部品の中の地と比べる。部品の縁に常に接する影がある場所では、影の色を指定の不透明度のまま地に重ねた色とも比べる |
| 計算 | WCAG 2 の相対輝度とコントラスト比の式。半透明の色と不透明度は、下の色に重ねて表示される色で計算する。重ねた色は、各成分を四捨五入（0.5 は切り上げ。JavaScript の `Math.round` と同じ）して 8 ビットにしてから比を計算する。比は小数第 3 位を四捨五入して書く |
| 対象外 | 押せない状態の表示。飾りの線・区切り線・カードの外形線。文字に添えた印（記号だけの印を含む）と飾り。値を文字でも出す小さな図（受験画面のステップ表示の丸の枠と地と線など）。文字のボタンの枠（文字で見分けられるので部品の基準の対象外。文字と地の組は文字の基準で確かめる） |
| 確かめ方 | 文字は axe の `color-contrast`（E2E。M7-exam-51）と、axe が見ないホバー・押下・訪れたあとの色をトークンの値から計算する単体テスト（M7-exam-13）。部品の 3:1 は axe が調べないため、トークンの値から計算する単体テスト（M7-exam-16）で確かめる |

### 8.2 配色の規則

基準に届かない組の直し方と書き方は、11 総論 8.3 の配色の取り決めによります（K-48・K-50）。

- 変え方: 組の片方の色だけを変える（白い文字の地なら地、明るい地の上の色の文字なら文字、部品なら部品の色）。参照元の色の HSL の色相と彩度を保ち、明度だけを 0.5% ずつ下げ、基準に届く最初の色（いちばん明るい色）にする。HSL から作る色も §8.1 の丸め方で 8 ビットにする。
- 状態で地が変わる文字: 参照元が状態（ホバー・押下・選んだとき）で文字の色を変えていないときは、文字の色を状態で変えずに、どの状態の地の上でも 4.5:1 に届く 1 つの色にする。参照元が状態で文字の色を変えているときは、状態ごとに確かめる。
- 影: 計算に入れるのは、部品の縁に常に接する影（部品自身の影と、すぐ隣にいつもある部品・帯の影）だけ。開いている間だけ重なる影やマウスを載せている間だけかかる影などは入れない。
- プレースホルダー: 色と `opacity: 1` を必ず指定する（ブラウザの既定で薄くならないように）。白の地の上は #767676。
- 焦点の見た目: 参照元が焦点の見た目を定めている部品（参照元の CSS に、その部品に当たる `:focus`・`:focus-visible` の規則がある部品）は参照元どおりにする（基準に届かない色は上の方法で直す）。定めの無い部品は本書の枠にする: キーボードで操作したとき（`:focus-visible`）だけ、2px #3F8DA5 の線を部品の縁から 2px 外側に描く。受験者側は管理画面に共通の焦点の枠（11-8 §2.2.6）を使わず、受験者側の指定として `exam.css` に書く（形と色は同じ）。受験者側の画面では、入力欄・プルダウンが参照元どおり（焦点のときにブラウザの輪郭を出さない）、ボタン・リンク・ラジオボタンが本書の枠、R-07 の箱が輪郭なし（11-1 §2.1.5・§2.1.7）。枠は、スクロールする枠で切れず、隣の部品に重ならない。
- リンク: ふだん・訪れたあと・ホバー・押下の 4 つの状態の文字の色を CSS に明示する（`:link`・`:visited`・`:hover`・`:active` の順。ブラウザの既定の色を使わない）。
- トークンと比: 11-1 §2.1.3 が正（K-48 で変えた 12 組、K-50 で変えた 4 組と、基準に届いていて変えない組・部品）。
