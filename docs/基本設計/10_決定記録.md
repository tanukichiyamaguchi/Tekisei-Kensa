## 2. 補足

- K-04 について: 放置された下書きには氏名・電話番号が含まれるため、個人情報保護の観点では一定期間後の削除が望ましいと設計時に指摘していました（02 D02-31）。依頼主の決定により削除しませんが、管理者が個別に論理削除することは引き続き可能です。将来削除する場合は 02 §11.16 の関数をそのまま使えます。
- K-05 について: 画像はプレースホルダーではなく本番で使う前提の簡素なイラストとして作成します。依頼主が後日正式な画像を提供する場合は、同じファイル名で差し替えるだけで反映されます。
- K-06 について: K-04「データは削除しない」は Firebase でも有効です。1.x 版の 02 で定義のみ残していた物理削除の SQL 関数（`purge_deleted_respondents()`・`purge_abandoned_sessions()`）は Firestore には存在しないため廃止し、将来物理削除する場合は Admin SDK のスクリプトとして改めて設計します。K-01〜K-03・K-05 は技術構成に依存しないため、そのまま有効です。Firebase 固有の仕様で設計時に確信が持てない点（セッション Cookie の有効期限の上限、`null` の等価クエリ、集計クエリの制約など）は 00 §8 の D-28〜D-34 と各分冊で「実装時確認」と明記しています（一覧は 09 §6.4 の 1〜46）。
- K-06 後の分冊間整合（2026-09-21。00 2.1 版、01・02・04・08 2.1 版、03・05・06・07 1.4 版、09 1.2 版）で、次の 3 点が新たに依頼主の判断を要する事項として 09 §6.1 に追加されました（仮置きのまま実装します）: (19) 管理者セッション Cookie の有効期間 7 日・延長なし（04 D04-53）、(20) 管理者追加用リンクはアカウント画面に常時表示せず、オーナーが「発行」したときにだけ 1 回表示する（04 D04-56、02 D02-35。要件定義書 §6.2 A-12 との差異）、(21) メールアドレス変更は確認メールを送らず即時反映し、変更後は再ログインを求める（04 D04-57）。パスワード・メールアドレス変更時の現在のパスワードによる再認証（09 §6.1 の 12）も引き続き未回答です。
