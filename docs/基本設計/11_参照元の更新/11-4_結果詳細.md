## 0. この文書について

### 0.1 位置づけ

- 本書は、参照元の結果詳細の更新（2026-11-04 取得）をアプリに再現するための領域別仕様書で、M7 の総括 `docs/基本設計/11_参照元の更新への追従.md` の下に置く。実装担当が本書だけを見て、結果詳細の画面（AI 解説・類似分析・PDF・経年比較の中身を除く）と、それに要る文言マスタ・表示用の関数・グラフの部品を作れる粒度で書く。
- 本書と既存の分冊（06 §2・§3.5・§4〜§7・§9〜§12、00 §1.5・§1.11・§3.3・§8、03 §8・§9、07 §9.4〜§9.6、付録C §2・§3・§5・§7、付録E）が食い違うときは本書を正とし、4 章のとおり各分冊を改版する。
- 選択肢は書かない。依頼主の決定（10 の K-20〜K-40）を当てはめた最終の仕様だけを書く。参照元と変える箇所は「参照元: …／アプリ: …（K-xx）」と書く。
- 寸法・色・文言は参照元の定義から書き写した。参照元の CSS の勝ち負け（§0.3）を解いた最終の値を書き、すべての見た目の値は別表D に CSS として載せる。推定は「推定」、取得物から分からないものは「未確認」と書き、6 章にまとめる。

### 0.3 根拠の書き方

- 参照元の定義: 「参照元定義（2026-11-04 取得）の …」と書き、ページ・再利用要素・HTML アプリ・ポップアップ・スタイルの名前と、必要なら要素 id で示す。以下、本文では「参照元定義の …」と略す。本書の主な定義は次のとおり。
  - 結果詳細の再利用要素「re: 診断結果」。その中のまとまり Group 回答データ（bUliR。見出しから新しいレイアウトまでを縦に並べる）、見出しのまとまり Group T（bUlCH）・g:title（bUlCL）、比較組織のプルダウン（bUlCS）、見出しの文字（bUlCT）、AI 解説のまとまり Group AI（11-6）。旧レイアウトのセクション（サマリー・個人特性・組織との相性・育成方法・ソーシャルスタイル）と、ポップアップ「Popup: ポイントが大きい場合の特性」「Popup: ポイントが小さい場合の特性」、第二候補の開閉（bUlfE）。
  - 結果詳細の中の HTML アプリ: rs-v2（新しいレイアウトの 7 セクションのすべてと、アイコン・折りたたみ・資質の割合の追加の処理）、rs-style（rs-v2 の見た目の上書き。rs-fx2〜rs-fx14 の style。最初の style は旧レイアウトのグラフ用で本書では使わない）、rs-nav（目次）、rs-meta（受験情報の 1 行）、rs-data（受験日・職業・タイプ・信頼係数・氏名の受け渡し）、rs-cmp（比較の値の受け渡し）。
  - 管理画面ページ admin_page の FloatingGroup D（結果詳細の枠）、Group I（「回答一覧に戻る」のボタン Button B と 1 年経過の帯）、Group N（スクロールする領域）。
  - スタイル Button_gameplan__small_green_w_icon_（類似分析・ダウンロードのボタン）、Text_gameplan_h1__38px_inner_tight__（見出しの文字）、Popup_popup_standard___dark_light_（ポップアップ）。色トークン primary（#3F8DA5）・primary_contrast（#FFFFFF）・text（#4C4B4B）・surface（#D5D5D5）。
- CSS の勝ち負け: 参照元のページでは rs-style の style が rs-v2 の style より前にある。このため rs-style のうち `!important` の付かない指定は、rs-v2 の同じ詳細度の指定に負ける（例: 平均の線、行の余白と角丸）。本書と別表D の値は、これを解いた最終の値で、参照元の画面（比較組織＝組織全体）の画素でも確かめた。
- 参照元の画面: 「参照元の画面（2026-11-04）」と書く。オーナーでない管理者のアカウントで、在籍の受験者 1 人の結果詳細を、比較未選択と比較組織＝組織全体で開いたもの（伏せ字済みの文字とスクリーンショット）と、並び替え・項目の説明・第二候補・接し方のタブ・ポップアップを操作した後の画面。比較組織を選んだ状態の文字は取得しておらず、スクリーンショットだけで確かめた。
- アプリと前回の仕様: リポジトリのパス（例 `components/admin/result/ResultSections.tsx`、`docs/基本設計/06_画面設計_管理者.md` §3.5）。

### 0.5 K-19 の置き換え

画面の文言は置き換え後のアプリの文言で書き、置き換えた箇所は（参照元: …）で原文を残す。本書の範囲で置き換えるのは次の 4 つで、どれも K-19 の規則どおりで言い換えに迷うものは無い。

| 16の特性の 2 つ目の凡例 | サロン平均（{比較組織}）／サロン平均（右上で比較組織を選ぶと表示されます） | 医院平均（{比較組織}）／医院平均（右上で比較組織を選ぶと表示されます） |

- 画面の状態（たたみ方・並び・タブなど）は保存しない（ブラウザのタブでページを開いている間だけ。§2.8.6・§2.16）。

### 3.2 API

- 変えない。結果詳細は `GET /api/v1/admin/results/{resultId}`（`ResultDetailDto`。04 §5.4。Server Component では `getResultDetail`）、比較は `GET /api/v1/admin/results/{resultId}/comparison?scope=…`（`ComparisonDto`。04 §5.5）を今のまま使う。監査ログ（`result.view`・`result.comparison`）とエラー（404 `RESULT_NOT_FOUND`、409 `POPULATION_EMPTY`）も今のまま。
