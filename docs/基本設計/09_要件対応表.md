## 0. 本書の位置づけ

本書は、基本設計 00〜08 の最終点検の成果物です。次の 3 つを確定します。

1. 要件定義書 §6 の機能要件（U-01〜U-09、A-01〜A-13、§6.3 採点、§6.4 文言、V-01〜V-09、§6.6 AI 解説）と §7 の画面（S-01〜S-11）が、どの分冊のどの節で設計されているかの対応表（§2、§3）。
2. 要件定義書 §11 の既存不具合 10 件と、依頼主の決定事項 1〜6 が、どの分冊で担保され、どのテストで確認されるかの対応表（§4、§5）。
3. 最終点検で見つけた分冊間の不整合と、その解消のために各分冊に加えた修正の一覧（§1）、および残った未解決事項（§6）。

本書は新しい設計を追加しません。対応表の「設計箇所」は各分冊の節番号を指し、内容はその分冊が正です。本書と分冊が食い違う場合は分冊を正とし、本書を直します。

1.1 版の注記（10 K-06）: 技術構成が Supabase から Firebase に変更され、01・02・04・08 は全面改版されました。これらの分冊の節番号と設計判断 ID（D01-xx、D02-xx、D04-xx、D08-xx）は改版後に変わるため、§2〜§6 では **01・02・04・08 への参照を節番号ではなく分冊名と対象（例: 「02（Firestore データモデル）`fetchPopulation()`」）で示します**（D09-04）。00・03・05・06・07 の節番号はそのまま参照します。08 のテスト ID（U-xx、I-xx、E-xx、H-xx、A-xx、PF-xx）は 1.0 版時点のもので、08 の改版で ID が変わった場合は 08 を正とします。§1 は 1.0 版時点の点検記録であり、改版しません。

1.2 版の注記（分冊間整合）: 01・02・04・08 の 2.0 版が出そろった後、5 名が並行して改版した結果の不整合（リポジトリ関数名・型名、Cookie の有効期間、招待リンクの表示方法、CI の分担、プロジェクト ID、イラストのパスなど）を 00 §6 の優先順位（関数名・型名・コレクションは 02、API 契約は 04、環境変数・スクリプト名・CI は 01、テスト ID は 08）で解消し、00 2.1 版、01・02・04・08 2.1 版、03・05・06・07 1.4 版として改版しました。各分冊の「他分冊への申し送り」節は反映状況を追記済みです。本書は §2.2 の A-12・A-13、§2.7、§6.1・§6.2・§6.4 を更新し、§6.4 に 01・02・04・08 が新たに挙げた実装時確認事項（20〜46）を追加しました。01・02・04・08 の節番号は 2.1 版で確定したため、§6 では節番号・設計判断 ID を併記します。
