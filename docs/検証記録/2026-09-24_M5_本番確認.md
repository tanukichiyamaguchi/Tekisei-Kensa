## 3. 見つかった不具合と対応

### 3.1 ログイン画面が 500（PR #11）

- 症状: `/admin/login` が 500。ログは `Failed to load external module firebase-admin-…/auth: Error [ERR_REQUIRE_ESM]: require() of ES Module …/jose@6…/index.js from …/jwks-rsa@4.1.0/…/utils.js not supported.`
- 原因: Vercel の関数実行環境では CommonJS から ES Module を `require()` できない。`firebase-admin/auth` が使う `jwks-rsa@4.1.0` が ES Module 専用の `jose@6` を `require()` していた。ローカル・CI の Node 22.22 は `require(esm)` が有効なため再現しなかった（`node --no-experimental-require-module` で再現）。
- 対応: `package.json` の `pnpm.overrides` に `"jwks-rsa>jose": "^5.10.0"`。`ci.yml` に `require(esm)` を無効にした Node で `firebase-admin` を読み込む確認を追加。
- 未確認: Vercel の実行環境で `require(esm)` が使えない理由（Node のバージョンか実行時の設定か）。

### 3.2 オーナーのメールアドレスが実行ログに表示された（PR #12、10 K-17）

- 症状: `firebase-ops` の `create-owner` の実行ログで、ステップ見出しの `env` 一覧にメールアドレスがそのまま表示された。リポジトリは公開のため誰でも閲覧できる状態だった。
- 原因: メールアドレスをステップの `env` で渡しており、`::add-mask::` をそのステップの中で実行しても見出しの表示に間に合わなかった。
- 対応: ジョブの最初のステップで `$GITHUB_EVENT_PATH` の `.inputs.email` を読んで `::add-mask::` に登録し、`create-owner` のステップでは `env` に置かずペイロードから読む。該当の実行ログの削除を依頼主に依頼した。

### 3.3 PDF が `browser_launch_failed`（PR #15）

- 症状: PDF のダウンロードが 500。ログは `pdf.export`・`reason: "browser_launch_failed"`（352ms）。
- 原因: Next.js 16.3.6 の Turbopack ビルドでは `outputFileTracingIncludes` が適用されない（`node_modules/next/dist/build/index.js` は `bundler !== Turbopack` のときだけ `collectBuildTraces` を呼ぶ）。そのため `@sparticuz/chromium` の `bin/`（圧縮済み Chromium）が PDF の関数に同梱されていなかった。手元の Turbopack ビルドの `route.js.nft.json` には `package.json` だけが含まれていた。
- 対応: `package.json` の `build` を `next build --webpack` に変更。`outputFileTracingIncludes` は pnpm の実体パス（`./node_modules/.pnpm/@sparticuz+chromium@*/node_modules/@sparticuz/chromium/bin/**`）を指定。`ci.yml` に、PDF の関数の nft.json に `chromium/bin/chromium.br` が含まれることの確認を追加。
- あわせて、失敗時のログ（`ai.generate`・`pdf.export`）に `detail`（例外クラス・HTTP ステータス・API や Chromium のエラー文 300 文字まで）を追加した。

### 3.4 回答一覧が 500（PR #14、10 K-19）

- 症状: `/admin` が `RangeError: 未知の職業コードです: 9` で 500。
- 原因: K-19 で職業の選択肢を歯科向け 9 項目からアイリスト向け 8 項目に変えた際、「本番にはまだ受検データが無い」と判断したが誤りだった。変更前に旧選択肢の「その他」（コード 9）で受検した 1 件があった。
- 対応: 保存済み文書の検証（`storedOccupationCodeSchema`）は 1〜9 を読み、旧コード 9 は「その他」と表示する。新規の登録は 1〜8 だけを受け付ける。

### 3.5 AI 解説が `invalid_request`（設定で解決）

- 症状: AI 解説の生成が 502。ログは `ai.generate`・`reason: "invalid_request"`。§3.3 の `detail` 追加後、理由が `status=400 type=invalid_request_error message=This API key is not scoped to a workspace, so this request must include the anthropic-workspace-id header …` と分かった。
- 原因: `ANTHROPIC_API_KEY` がワークスペースに属さないキーだった。
- 対応: 依頼主が Anthropic Console でワークスペースに属するキーを発行し、Vercel の `ANTHROPIC_API_KEY`（Production・Preview）を差し替えて再デプロイした。コードの変更はない。**運用上の注意: Claude API のキーは、ワークスペースに属するものを使う。**

### 3.6 医療系の文言（PR #13、10 K-19）
