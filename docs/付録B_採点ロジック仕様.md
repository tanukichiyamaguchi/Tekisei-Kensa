# 付録B 採点ロジック仕様（計算式）

本付録は、既存システム（first-inspection.jp、Bubble.io 製）の受検完了時ワークフロー（user_form ページ「診断完了」ボタン）から復元した計算式です。式は Bubble の評価順（左から右へ順次評価、演算子の優先順位なし）で記述されており、ここでは加算・減算のみのため通常の数式と同値です。

記法: `Q12.スコア` は「設問 12 の回答選択肢に紐づく配点属性『スコア』の値」を表します。

## 1. 選択肢ごとの配点属性

5 件法の各選択肢は、9 種類の配点属性を持ちます。指標ごとにどの属性を使うかが異なります。

| 選択肢 | スコア | 信頼係数 | +ソーシャル | -ソーシャル | スコア(重要) | スコア(相性) | スコア(-相性) | スコア(タイプ用) | ソーシャル(重要) |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| そう思う | 2 | 1 | 5 | -2.5 | 3 | 5 | 5 | 2 | 7.5 |
| どちらかと言えばそう思う | 1.5 | 1 | 2.5 | -1.25 | 1.5 | 3 | 3 | 1 | 3.75 |
| どちらでもない | 1 | -0.5 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| どちらかと言えばそう思わない | 0.5 | 1 | -1.25 | 2.5 | -1.5 | -3 | -3 | -1 | -2.5 |
| そう思わない | 0 | 1 | -2.5 | 5 | -3 | -5 | -5 | -2 | -5 |

補足:

- 「信頼係数」属性は、「どちらでもない」を選ぶと −0.5、それ以外は +1 になります（中立回答の多さで信頼性を下げる設計）。
- 「+ソーシャル」「-ソーシャル」は符号が反転した対の属性で、資質タイプ得点の加点・減点に使われます。
- 「スコア(相性)」「スコア(-相性)」は同じ値ですが、計算式上は加算項に前者、減算項に後者が使われています。

## 7. ソーシャルスタイル 4 分類（0〜30）

```
Driving    = max(タイプ得点 for タイプ in 組織内分類=driving)    / 2
Expressive = max(タイプ得点 for タイプ in 組織内分類=expressive) / 2
Amiable    = max(タイプ得点 for タイプ in 組織内分類=amiable)    / 2
Analytical = max(タイプ得点 for タイプ in 組織内分類=analytical) / 2

同点時の優先順位 = Driving が最優先、Amiable が最劣後（Expressive と Analytical の間の順位は未確認）
```

実データ 73 件すべてで「ソーシャルスタイル」フィールドは 4 値の最大値を持つ分類のいずれかでした。4 値に同点がある行は 15 件あり（4 分類すべて同点の行を含む）、その結果は `Driving > Expressive > Analytical > Amiable` または `Driving > Analytical > Expressive > Amiable` のどちらの優先順位とも矛盾しません（Expressive と Analytical が同点で最大となる行は存在しなかったため、この 2 つの順位は判別できません）。新システムでは `Driving > Expressive > Analytical > Amiable` を採用し、Expressive と Analytical の順位は仮置きであることを明記してください。値は 0.25 刻みです（タイプ得点は 0.5 刻み、それを 2 で割るため）。

## 8. 信頼係数（0〜100）

```
raw = Σ_{q=1..144} Q(q).信頼係数  − 144      # そう思う等: +1、どちらでもない: −0.5
信頼係数 = raw × 0.49 + 100
信頼係数 < 0 なら 0
```

「どちらでもない」を n 問選ぶと raw = −1.5n となり、信頼係数 = 100 − 0.735n です（n=136 で 0 付近）。対象は Q1〜Q144 のみで、Q145〜Q204（ソーシャルスタイル系設問）は含まれません。

## 9. 比較組織との合致度・偏差値・評価（管理画面で算出）

管理画面で「比較組織」（組織全体、または A〜Z チーム）を選択した時点で、閲覧中の管理者アカウント（User）に一時計算値を書き込み、その値を表示します（回答データ自体には保存されません）。

```
# 比較母集団 P = 同一組織（同一パスワード）の回答データのうち「除外」でない受検者（チーム選択時はそのチームのみ）
avg(X) = P における X の平均

# 16 尺度ごとの差分（絶対値）
diff_i = |avg(尺度_i) − 受検者.尺度_i|      (i = 16 尺度)

# 合致度
合致度 = 100 − 0.5 × Σ diff_i
合致度 < 0 なら 0

# 相性 5 軸の偏差（受検者 − 平均）を 0〜100 換算
dev_axis = (受検者.axis − avg(axis)) / 2 + 50     (axis = 適応する環境, 適応する業務, 思考の傾向, 意思決定, ストレス耐性)
偏差値 = (dev_適応する環境 + dev_ストレス耐性 + dev_適応する業務 + dev_思考の傾向 + dev_意思決定) / 5

# 評価（上から順に判定し、最後に成立した条件が採用される = 最も良い評価が採用される）
評価 = "E"
if 合致度 >= 60 and 偏差値 >= 30: 評価 = "D"
if 合致度 >= 60 and 偏差値 >= 40: 評価 = "C"
if 合致度 >= 70 and 偏差値 >= 50: 評価 = "B"
if 合致度 >= 80 and 偏差値 >= 60: 評価 = "A"
```

既存システムの不具合（新システムでは修正を推奨）:

- 「思考の傾向」の偏差計算で、受検者側の値に誤って「適応力」（性格特性）を参照しています（`受検者.適応力 − avg(思考の傾向)`）。正しくは `受検者.思考の傾向 − avg(思考の傾向)` です。実データでも確認済み: 閲覧した受検者（思考の傾向 = 28、適応力 = 23、組織平均 21.61）の「思考の傾向(偏差値)」は 50.695 で、`(23 − 21.61) / 2 + 50` と一致します（正しい式なら 53.195）。
- 16 尺度の差分の一部（協力性・優劣性・発想力・こだわり・敏感さ・行動力）は「受検者 < 平均」のケースで除外者を含まない母集団、それ以外は除外者を含む母集団と、検索条件が統一されていません。

計算式の検証: 管理者アカウントに一時保存された観測値（差分 16 値、相性 5 軸の平均、各軸の偏差値、合致度 49.84、偏差値 68.689、評価 E）から、上記の式で合致度・偏差値・評価を再計算すると観測値と一致しました（`tests/verify_fixtures.py`）。

比較母集団について未確認の点: 観測された差分 16 値は 55 倍すると全て 0.5 の倍数になり、平均の分母が 55 件であったことを示します。一方、レーダーチャートに描画された組織平均 16 値は 75 倍で 0.5 の倍数になり、分母 75 件を示します。取得できた同一組織の回答データは 73 件（除外 4 件）で、全件・除外を除く・作成日時による区切りなど自然な部分集合のいずれでも上記の平均値を再現できませんでした。既存の母集団の正確な定義（サーバ側の検索条件、または旧レコードの扱い）は未確認です。新システムでは「同一組織・除外でない・現行ロジックで採点済み」の受検者を母集団と定義することを推奨します。
